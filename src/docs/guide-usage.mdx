# นำไปใช้ในระบบอื่น

มีสองวิธีในการนำไปใช้ และแนะนำวิธีแรก:

1. **`bun add` (แนะนำ)**: ติดตั้งเป็น dependency ใช้ `styles.css` และ import components จากแพ็กเกจ เวอร์ชันถูกล็อกด้วย tag และ `bun.lock`
2. **shadcn registry (`@moove`)** ตาม OMS ADR-009: โค้ดถูกคัดลอกเข้า repo ของแต่ละระบบ และระบบนั้นเป็นเจ้าของโค้ด ใช้เมื่อต้องแก้ component ในระบบนั้นโดยตรง

## ติดตั้งด้วย bun add

repo นี้เป็น private ใช้ภายในเท่านั้น ผู้ติดตั้งต้องมีสิทธิ์อ่าน repo (ขอได้จากทีม Design System) และตั้ง SSH key กับ GitHub ไว้แล้ว

```bash
bun add git+ssh://git@github.com/Nutrition-Plus/design-system-internal-tools.git#v0.3.2
```

แล้วตั้งค่า CSS หลัก (ไฟล์ที่มี `@import "tailwindcss"`):

```css
@import "tailwindcss";
@import "@moove/design-system/styles.css";
@source "../node_modules/@moove/design-system/dist-lib";
```

- บรรทัด `@source` จำเป็น ไม่งั้น Tailwind จะไม่สร้าง class ที่ใช้ใน components
- ตั้ง `<html lang="th" data-density="comfortable">` (หรือ `"compact"`) เหมือนวิธีด้านล่าง
- ต้องมี React 19 และ Tailwind CSS 4 ในโปรเจกต์ (เป็น peer dependency)

```tsx
import { useState } from "react"
import { useTable, type ColumnDef } from "@tanstack/react-table"
import { Button, DataTable, DatePicker, PageHeader, dataTableFeatures, type DataTableFeatures } from "@moove/design-system"

type Order = { id: string; orderNo: string }

// eslint-disable-next-line @typescript-eslint/no-explicit-any
const columns: ColumnDef<DataTableFeatures, Order, any>[] = [{ accessorKey: "orderNo", header: "เลขที่" }]

function Orders({ orders }: { orders: Order[] }) {
  const [date, setDate] = useState<Date | undefined>()
  const table = useTable({ features: dataTableFeatures, columns, data: orders, getRowId: (r) => r.id })
  return (
    <>
      <PageHeader title="คำสั่งซื้อ" actions={<Button>สร้างคำสั่งซื้อ</Button>} />
      <DatePicker value={date} onChange={setDate} />
      <DataTable table={table} caption="รายการคำสั่งซื้อ" />
    </>
  )
}
```

ระบบต้องติดตั้ง `@tanstack/react-table` (v9) เองด้วย เพราะเรียก `useTable` โดยตรง DataTable รับ table instance ที่สร้างจาก `useTable` เสมอ

`dist-lib/` ถูก commit ไว้ใน repo เพื่อให้ติดตั้งจาก git ได้โดยไม่ต้อง build ก่อน เมื่อแก้ `src/` ต้องรัน `bun run build:lib` และ commit ผลลัพธ์ด้วย (CI จะตรวจให้)

### ตั้งค่า CI ของระบบปลายทาง

CI ต้องอ่าน repo นี้ได้ตอน `bun install` ใช้ deploy key แบบอ่านอย่างเดียว:

1. สร้าง key คู่ใหม่ (ไม่ต้องตั้ง passphrase): `ssh-keygen -t ed25519 -N "" -C "ci-<ชื่อระบบ>" -f moove-ds-deploy-key`
2. ใน repo design system: **Settings → Deploy keys → Add deploy key** ใส่ `moove-ds-deploy-key.pub` และไม่ติ๊ก "Allow write access" (ทีม Design System หรือ admin เป็นคนเพิ่ม)
3. ใน repo ของระบบ: **Settings → Secrets and variables → Actions** เพิ่ม secret `MOOVE_DS_DEPLOY_KEY` เป็นเนื้อหาไฟล์ `moove-ds-deploy-key` แล้วลบไฟล์ key ออกจากเครื่อง
4. ใน workflow ให้โหลด key ก่อน `bun install`:

```yaml
- uses: webfactory/ssh-agent@v0.10.0
  with:
    ssh-private-key: ${{ secrets.MOOVE_DS_DEPLOY_KEY }}
- run: bun install --frozen-lockfile
```

ใช้ key แยกต่อระบบ จะได้ถอนสิทธิ์ทีละระบบได้

## โครงสร้าง

```
tokens/*.json                 ← แหล่งความจริงของ tokens (รูปแบบ W3C DTCG)
  └ bun run tokens            → src/styles/tokens.css (CSS variables + @theme + type-*)
                              → src/tokens/tokens.generated.ts (สำหรับเอกสาร)
                              → tokens/build/tokens.json (สำหรับ Figma / เครื่องมืออื่น)
src/styles/{fonts,base}.css   ← ฟอนต์และ base styles
src/components/ui/*           ← shadcn primitives ที่ปรับเข้ากับ MOOVE แล้ว
src/components/patterns/*     ← DataTable, ConfirmDialog, EmptyState/ErrorState, PageHeader, AppShell
registry.json                 → bun run registry:build → public/r/*.json
```

| ชั้น | อยู่ที่ | ใครดูแล |
|-|-|-|
| Tokens, primitives, patterns | repo นี้ (registry `@moove`) | ทีม Design System |
| Domain components (เช่น WorkStatusBadge, BlockerBadge) | repo ของแต่ละระบบ `src/components/domain/` | ทีมระบบนั้น |
| Feature screens | repo ของแต่ละระบบ | ทีมระบบนั้น |

## ติดตั้งผ่าน shadcn registry (Next.js หรือ Vite)

```bash
# 1. โปรเจกต์ที่มี shadcn แล้ว (components.json) ใช้ base: radix
bunx --bun shadcn@latest registry add @moove=<REGISTRY_HOST>/r/{name}.json

# 2. ติดตั้ง theme และ components ที่ต้องใช้
bunx --bun shadcn@latest add @moove/moove-theme @moove/button @moove/data-table @moove/app-shell
```

3. แก้ไฟล์ CSS หลัก (`tailwindCssFile` ใน components.json) ให้เหลือเท่านี้ **และลบ `:root`, `.dark`, `@theme inline` เดิมของ shadcn ออก** (ถ้าไม่ลบ ค่าเดิมจะทับ tokens ของ MOOVE)

```css
@import "tailwindcss";
@import "tw-animate-css";
@import "shadcn/tailwind.css";
@import "./styles/moove/fonts.css";
@import "./styles/moove/tokens.css";
@import "./styles/moove/base.css";
```

4. ตั้ง density และภาษาที่ `<html>`: `<html lang="th" data-density="comfortable">` (iPad/touch) หรือ `"compact"` (desktop)
5. ห่อแอปด้วย `<TooltipProvider>` และใส่ `<Toaster />` หนึ่งครั้ง

> ทดสอบขั้นตอนนี้แล้วกับโปรเจกต์ Vite ใหม่ (`shadcn init -t vite -b radix`): ติดตั้งผ่าน registry, typecheck และ `vite build` ผ่าน

## อัปเดตเมื่อ design system ออกเวอร์ชันใหม่

ไฟล์เป็นของแต่ละระบบแล้ว การ `add` ซ้ำจะทับการแก้ไข จึงต้องดู diff ก่อน:

```bash
bunx --bun shadcn@latest add @moove/button --dry-run
bunx --bun shadcn@latest add @moove/button --diff button.tsx
```

- ไฟล์ที่ไม่ได้แก้เอง → ทับได้
- ไฟล์ที่แก้เอง → merge ด้วยมือ แล้วพิจารณาเสนอการแก้นั้นกลับมาที่ design system
- `moove-theme` (tokens) ควรอัปเดตตามเสมอ เพราะไม่ควรมีการแก้เฉพาะระบบ

## สิ่งที่ปรับได้และไม่ควรปรับ

| ปรับได้ต่อระบบ | ไม่ควรปรับ (เสนอเข้า design system แทน) |
|-|-|
| density, ชื่อระบบ โลโก้ เมนูใน AppShell | ค่าสี ฟอนต์ type scale radius |
| คอลัมน์และแท็บของตาราง, ขนาดหน้า | ความหมายของสีสถานะ |
| domain components, ข้อความในแอป | ความสูง control, focus ring |
| ความกว้างเนื้อหาของหน้า | พฤติกรรมของ Dialog, DataTable, Form |
